# 12. Типи організацій: ОСББ і УК

## Навіщо

**Мій дім** обслуговує не лише самоуправління співвласників (**ОСББ**), а й **управляючі компанії (УК)**, які ведуть один або кілька будинків за договором.

## Поле моделі

```
Tenant.orgType: osbb | management_company
```

- Default для існуючих записів: `osbb`
- API: `POST/PATCH /tenants` приймає `orgType`
- Login / `GET /auth/me`: `user.tenant.orgType` для UI-лейблів

## Порівняння

| | ОСББ (`osbb`) | УК (`management_company`) |
|--|---------------|---------------------------|
| Оператор | правління співвласників | управляюча компанія |
| Multi-building | будинки одного ОСББ | портфель об’єктів |
| `chairman` (label) | Голова правління | Керівник |
| `board` | Член правління | Працівник УК |
| `auditor` | Ревізійна комісія | Контроль (опційно) |
| Мешканці | без змін | без змін |
| Фінанси / нарахування / PWA | однакові | однакові |

## Що *не* змінюється

- Коди ролей JWT / Prisma enum (`chairman`, `board`, …)
- Права RBAC (permissions matrix)
- Структура фондів, FIFO-платежів, квитанцій

## Що змінюється

- Тексти UI / інструкцій / email
- Підказки в майстрі setup і на `/admin/tenants`
- Майстер setup — **per tenant** (`X-Tenant-Id`); нова org з `/tenants` стартує з `Building.isInitialized = false`
- Заголовок кабінету: «Кабінет правління» vs «Кабінет УК»

## Рекомендації

1. Для УК одразу планувати кілька `Building` під один `Tenant`.
2. Не змішувати різні юридичні особи в одному tenant без потреби — краще окремі tenants.
3. Ребрендинг пакетів `@dah/*` — окремий етап (не блокує orgType).
